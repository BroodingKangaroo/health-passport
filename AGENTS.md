# AGENTS.md

Repo: **HealthPassport** — FastAPI backend + Next.js (React 19) frontend, two independent apps under `backend/` and `frontend/`. No workspace build tool ties them; run/test them separately.

## Read these before touching an area

Deep architecture details live in on-demand docs — read the relevant one first, don't rely on AGENTS.md alone:

- `backend/docs/architecture.md` — reference model, unit canonicalization, `/api/extract` persistence rules, delete/merge semantics, DB migration.
- `frontend/docs/architecture.md` — proxy rewrites, reference formatting, merge/unit-conflict UI contracts, settings tab.
- `backend/e2e/README.md` — golden harness, isolated-server rules, add-case workflow.

**Keep docs in sync — only for significant changes**: update the affected
on-demand doc(s) — `backend/docs/architecture.md`,
`frontend/docs/architecture.md`, `backend/e2e/README.md`, and the AGENTS.md
invariants if they change — **in the same change, but only when the change
makes a documented statement false** (an observable contract: API shape,
persisted data model, reference/status semantics, matcher/unit rules, proxy
rewrites, merge/unit-conflict UI behavior, harness/safety behavior). Skip
doc updates for cosmetic or mechanical changes — typos, formatting, internal
renames, tests, tooling/dependency bumps, log messages — without flagging
them. For refactors that keep observable behavior identical, skip doc edits
but state in your report that no documented statement changed. When in doubt,
flag drift to the user rather than editing docs. AGENTS.md is the index, the
architecture docs are the truth.

## Quick commands

- Backend API: `uvicorn app.main:app --port 8000` (from `backend/`, venv active; venv at `backend/venv/`).
- Backend tests: `python -m pytest tests/ -v` (from `backend/`). In-memory sqlite via `tests/conftest.py`; no DB setup or `MISTRAL_API_KEY` needed.
- Backend lint: `venv/bin/ruff check .` (from `backend/`).
- Frontend dev: `pnpm dev` (port 3000). Lint: `pnpm lint`. Unit tests: `pnpm test` (vitest run, jsdom, `@/` → `src/`). No frontend e2e suite — backend golden harness covers e2e.
- Seed LOINC: `python -m app.db.seed_loinc` — **drops and recreates the DB**. LOINC dictionary is the single source of truth for biomarker definitions. Run once; keep stable while a golden is in use.
- E2E: `python backend/e2e/run_e2e_server.py` (isolated uvicorn, own DB; never port 8000, never `pkill`).
- Extraction benchmark (ISSUES.md #24): `venv/bin/python benchmark/run_benchmark.py --runs 3` from `backend/` — LIVE pipeline over `benchmark/corpus/`, real Mistral spend; loop usage in `.opencode/skills/autoresearch/SKILL.md` and `benchmark/README.md`.
- Public demo via tunnel: `scripts/demo-tunnel.sh` (from repo root) — starts backend (:8000) + production frontend (:3000, `NEXTAUTH_URL` set to the fresh URL) + a free pinggy tunnel, then prints the public URL; `--rebuild` forces a frontend build, `--stop` tears everything down. Free URL expires in 60 min; re-run for a fresh one (users must re-login — cookies are per-domain). Uses the real dev DB; run `seed_loinc` once on a fresh machine.

## Backend invariants (always true)

- **Required env**: `MISTRAL_API_KEY` (in `.env`) — OCR/extraction/matching in `ai.py`. `.env` and `.jwt_secret` are gitignored dev-only secrets (not committed). **Mail env**: `FRONTEND_URL` is the base of every link in outgoing email (unset → links point at `localhost:3000`), `SMTP_ENABLED` + `SMTP_*` configure the transport, and `ENVIRONMENT=production` disables the dev fallback that logs one-time links when SMTP is off; see `backend/.env.example`.
- **Reference model**: every biomarker definition and reading carries a single structured `reference` JSON column whose `kind` IS the result type — `{kind:'interval', low, high}` numeric, `{kind:'qualitative', expected}` text. No separate `result_type`; the kind is the sole discriminator. `status` is `low|normal|high` for intervals, `normal|abnormal` for qualitative, `""` (unknown) for a numeric value against an unrecognized qualitative expected, **computed at save time and persisted** to `biomarker_readings.status` (not recomputed on read).
- **CRITICAL — `/api/extract` persists definitions**: matching runs in a worker thread (`backend/app/api/ai.py`, `_match_in_thread`) using its own `SessionLocal()`. It MUST `commit()` before `close()` (and `rollback()` on error), or definitions + canonical units are silently lost and sequential extractions "forget" units. #1 thing to check.
- **Unit canonicalization** (`app/services/matcher/` package — facade `__init__.py`, units in `units_conversion.py`/`units_guess.py`): canonical unit set on the FIRST reading that creates the def (first-seen wins), and it is ALWAYS the linear magnitude — a log-scale raw unit (`lg копий/мл`) strips to `copies/mL` at anchor time with the def's reference scaled `10^x`; the `lg` prefix still MEANS log10 (values convert via the deterministic `10^x` scale function — never treat lg values as linear). Ratio-like analytes anchor `ratio` (unless the document prints a percent unit — a printed `%` is a real unit, e.g. P-LCR), qualitative screens anchor `""`. Later readings converted via `scale_function`; empty units handled by `_guess_unit()`, never the batch LLM translator. Existing lg-anchored defs were migrated by `scripts/migrate_lg_to_linear.py`.
- **Specimen-aware matching**: extraction sets `specimen` (record-level main material + per-row override) and the matcher resolves `data/specimen_synonyms.json` before the generic table, rejects recall-driven matches whose LOINC SYSTEM conflicts (`_specimen_compatible`), and qualifies urine/feces local defs (`"Protein (urine)"`, qualifier in the id hash) so the same analyte in different biomaterials never unifies. Curated matches are authoritative and exempt from the SYSTEM guard.
- `app.log` is a generated runtime artifact.
- New columns are added to existing DBs by `migrate_add_columns()` in `app/db/session.py` (called from `init_db`).
- **Response localization**: user-facing `detail`/SSE/success strings go through `app/i18n.py` (`i18n.tr`), localized EN/RU by the request's `Accept-Language` (pure-ASGI `LocaleMiddleware` + ContextVar; EN byte-identical default). Never hardcode new user-facing strings in routers — add a catalog key. OCR errors are localized in `ai.py` from `OCRProcessingError.kind` (classification runs in a thread without the locale).
- **Session version — a token can be revoked**: every JWT carries the account's monotonic `patients.token_version` as the `tv` claim, and `get_current_user` rejects a token whose claim is behind the row (`auth.session_invalidated`, 401). It is bumped in the SAME transaction as password change, password reset and confirmed email change — that is what makes the emailed "reset your password immediately" advice evict a stolen session instead of being cosmetic. Tokens minted before the column existed carry no claim and read as `0` (the column default), so the migration logs nobody out. The rejection is a *typed* marker (`TokenStaleError`, sibling of `TokenExpiredError` under `ReauthRequiredError`), so `get_current_user_or_anon` forces re-auth rather than silently degrading to an anonymous session.
- **Email identity is normalized**: addresses are trimmed + lowercased on every WRITE (register, both email-change paths, `create_user`) and `get_user_by_email` compares the normalized form — pydantic's `EmailStr` lowercases only the domain while SQLite's `UNIQUE` index is case-sensitive, so unnormalized addresses were two accounts on one mailbox. Legacy rows are rewritten by `migrate_normalize_emails()` in `init_db`; rows differing ONLY by case are two accounts claiming one mailbox (a product decision), so the migration logs them and leaves them untouched instead of crashing the index. Consequently `POST /api/auth/change-email` answers a UNIFORM 200 when the address belongs to another account (a 409 there was a user-enumeration oracle) and emails that address a "someone tried to use it" notice.
- **Email change (roadmap 0.4)**: `POST /api/auth/change-email {current_password,new_email}` stages a 30-min single-use `email_change_tokens` row (SHA-256 hash + pending address, never the raw token) and mails the confirmation link to the NEW address; `patients.email` is rewritten ONLY by `POST /api/auth/confirm-email-change {token}` (public, like reset-password), which also notices the OLD address. Double opt-in is the contract: a request alone changes nothing, so a typo cannot lock the owner out. Mail leaves the request path via `BackgroundTasks` + `mailer.deliver`, so delivery timing cannot reveal whether an account exists.
- **Batch import (staged extraction jobs, `app/services/extract_jobs.py` + `app/api/import_jobs.py`)**: quota is charged at job SUBMIT and refunded on failure/cancel — never on disconnect. Results are STAGED (`ExtractionJob.result` + file); an entry exists only after review (save/merge with `import_job_id`, CAS `done→saving` claim, storage charged at save). Saving keeps the job as a `status='saved'` HISTORY row (result cleared, `saved_entry_id` set, never GC-expired); unsaved staged jobs/files/notifications expire after 72h (global lazy GC, which also skips in-flight `saving` claims). `saved`/`dismissed` rows are PERMANENT history; a dismissed done-extraction's file+result are kept so `POST /api/import/jobs/{id}/restore` can revive it within the 72h window (the sweep then frees just the file — `file_size` zeroed — closing the window; the row never disappears). The list summary carries `restorable` and `merge_conflicts` (batched list-time pre-check of the merge 409: definition/LOINC/name matching, same rule the merge endpoint enforces) so the /imports page can warn before the review editor. Worker owns refunds for anything it dequeued; API-side cancel/retry/restore act only via CAS transitions. One `Notification` row per job terminal transition, same commit as the status change; cancelled emits nothing (restore recreates the done notification). The SSE `/api/extract` path is UNTOUCHED (e2e golden harness unchanged). The queue is per-process — exactly ONE backend process per DB (pid-file guard at startup; `uvicorn --workers N` / scaled containers unsupported). Details in `backend/docs/architecture.md` → "Batch import".

- **Public share surface (roadmap 1.1, `app/api/share.py` + `app/services/share_links.py`)**: a share link is a THIRD principal class — no session, no cookie, no `UsageLimit`. The raw token is stored only as SHA-256 in `share_links.token_hash` (returned once, never re-displayable) and travels in the `X-Share-Token` HEADER, never in an API path or query (no log-scrubbing layer exists). `resolve_share_context` is the ONE place a client string becomes a tenant id: missing/unknown/revoked/expired all produce one identical localized 404. The public ENDPOINTS are GET-only (the same module also carries the three POST owner routes under `/api/share/links`, which authenticate normally), take no tenant id, no scope and no `include_*` override, and depend on the resolver rather than `get_current_user_or_anon` (which would mint an anonymous cookie). Responses are `no-store` + `noindex`; attachments never travel; merged readings are excluded; `canonical_unit_inferred` is dropped. `DELETE /api/auth/account` deletes the principal's links, and `copy_anonymous_data` RE-KEYS them (`owner_id` + `is_anonymous=False`). Details in `backend/docs/architecture.md` → "Public share surface".

## Frontend invariants (always true)

- API calls proxied server-side via `next.config.mjs` rewrites: `/api/*` (except next-auth paths) and `/static/*` → `STATIC_PROXY_URL` (default `http://localhost:8000`, Docker `http://backend:8000`). Don't add client-side API base URLs that bypass this. Rewrites apply to INCOMING requests only — a fetch the Next server itself makes (`src/services/share.ts`) addresses `STATIC_PROXY_URL` directly.
- **The public shared view (`/s/<token>`) lives outside `AuthProvider`**: route group `(public)` with its own root layout and no `src/app/layout.tsx`, or opening a link would fetch `/api/auth/session` and can mint an anonymous session for a stranger. It fetches with `cache: 'no-store'` (any cache breaks revocation), resolves its own locale (`?lang=` → `Accept-Language` → `NEXT_LOCALE` → `en`) and **never writes `NEXT_LOCALE`**. The shared tree must not import `services/api.ts`, `lib/auth-token`, `AuthProvider` or `QueryProvider` (a test walks the import graph), and reused components there get no navigation callback (`FlowsheetMatrix.onOpenBiomarker` omitted). Recipient strings live in `src/i18n/messages/sharedView.ts`, sender strings in `share.ts`.
- AI-guessed units (`canonical_unit_inferred`) are flagged ONLY in the add-entry editor (`LabResultForm.tsx`, blue ring + hover tooltip). The old amber `InferredUnitNote` triangle is **removed** from the timeline and flowsheet — do not re-add it there.
- Merged readings appear **only** in the timeline details view (`results-panel.tsx`) under `MergedSectionHeader`; flowsheet and print editor exclude them. `biomarkersAtDate` copies `merged`/`merged_source` from the reading AT the selected event (`isLatest`-gated) — never a `??`-fallback to the latest reading.
- **Event-type vs status color channels** (roadmap 0.6): type colors (`TYPE_VISUALS` in `src/lib/event-visuals.ts`, `--event-*` tokens) are categorical and paint only icon bubbles, rail nodes, filter-chip dots, and header chips; status colors stay semantic (`low`/`high`/`abnormal`); the primary accent is selection/focus only. Never mix the channels, never apply `event-*` tokens to the print editor. New `--event-*`/`--status-*` tokens must be defined under `:root`, `.dark`, AND the `prefers-color-scheme` fallback block in `globals.css` together.
- **UI locale (EN/RU)**: next-intl, cookie `NEXT_LOCALE` driven, NO URL routing (`next.config.mjs` must keep the `createNextIntlPlugin` wrapper). Catalogs in `src/i18n/messages/*.ts` (en/ru parity guarded by `src/i18n/__tests__/messages.test.ts`); EN values are pinned by ~280 existing test assertions — don't reword them. `services/api.ts` sends `Accept-Language` on every call. Tests rendering components with `t()` must wrap in `TestI18nProvider`. The printed document's own 7-language maps in `print-editor.tsx` are document-language, NOT UI locale — keep them out of the catalogs.

## Docker / CI

- `docker-compose.yml` builds both services; backend mounts `./backend/.env` and persists DB + uploads as volumes. Frontend needs `STATIC_PROXY_URL=http://backend:8000`.
- CI (`.github/workflows/tests.yml`): two jobs (backend pytest, frontend vitest), triggered on `backend/**` or `frontend/**`. The e2e golden harness is NOT in CI — run manually via `run_e2e_server.py` / verify with `validate_offline.py`.
