# HealthPassport code & UX audit — September 2026

Full-repo audit (backend + frontend + docs + live behaviour) from an agent-developer
and end-user perspective. Phase 0 items are **implemented and verified by tests**;
Phase 1/2 are prioritized, evidence-backed follow-ups.

Method: full pass over `AGENTS.md` invariants, both architecture docs, four parallel
code audits (backend / frontend / docs drift / UX), plus live checks against the
running dev servers (curl + headless Chromium). Every Phase 0 finding was
re-verified in source by the primary agent before fixing.

Severity: **P0** = crash or data-integrity/DoS, **P1** = user-visible incorrect
behaviour, **P2** = hardening, hygiene, stale artifacts.

## Phase 0 — done (crash + data-integrity fixes)

### 0.1 Unknown document type bricked the timeline
- **Symptom**: `/api/extract` can return `entry_type: "unknown"`; `add-entry.tsx`
  saved it verbatim, `entries.py` accepted any string, then
  `history-list.tsx:594` did `TYPE_VISUALS[event.type].icon` — no `unknown` key,
  so the whole timeline (and `/` landing gate) crashed into the error boundary.
- **Fix**:
  - `backend/app/api/entries.py` — `save_entry` validates `type` against
    `_ALLOWED_ENTRY_TYPES` (`blood_test | doctor_visit | instrumental_test |
    procedure`) and returns a localized 400 (`entries.invalid_entry_type`).
    `procedure` is a real savable type (seeded + rendered); `unknown` is an
    extraction OUTPUT only.
  - `frontend/.../add-entry.tsx` — `applyExtractedRecord` maps `unknown` to an
    empty type; the select gains a disabled placeholder, a dedicated amber
    "couldn't identify" callout replaces the success banner, `handleSave`
    blocks without a type and the Save button is disabled.
  - `frontend/src/lib/event-visuals.ts` — new `eventVisual(type)` safe lookup +
    neutral `UNKNOWN_EVENT_VISUAL` (no `--event-*` token by design); used by
    `history-list.tsx` for API-originated types. New `typeUnknown`/`chipUnknown`
    catalog keys (EN/RU).
- **Tests**: `test_entries.py::TestSaveEntryTypeValidation` (unknown / garbage
  rejected, procedure accepted, no entry created),
  `add-entry.test.tsx` ("blocks saving when the extractor could not classify"),
  `history-list.test.tsx` ("renders an unknown backend event type …").

### 0.2 Exponent DoS in reference/value parsing
- **Symptom**: `reference.py` computed `10 ** int(exp)` with only
  `TypeError/ValueError` caught. `"9*10^20000000"` spent ~16 s building a
  multi-million-digit int, then raised uncaught `OverflowError` (500) — reachable
  from a plain `POST /api/entry` value or reference string.
- **Fix**: `_bounded_exponent()` clamps `|exp| <= 308` before any math; both
  branches catch `OverflowError` and reject non-finite results; `parse_value`
  returns `None` directly for matched-but-invalid sci/pow forms instead of
  falling through to the "first number" fallback (which previously resurrected a
  misleading `9` from `9*10^20000000`). Glued-unit range sides clamped too.
- **Tests**: `test_reference_parsing.py` — hostile exponents reject fast,
  boundary `10^308` still parses, huge-exponent references become unknown.

### 0.3 GC sweep could delete live import jobs / double-refund
- **Symptom**: `sweep_expired_jobs` snapshotted candidates without a write lock
  and then deleted them unconditionally by PK. A concurrent CAS transition
  (worker claim, cancel, retry, dismiss, restore, save) could land in between:
  the sweep deleted a live job (worker commits definitions, staged file
  unlinked), and its stale snapshot could refund a job that had already been
  refunded.
- **Fix**: every sweep mutation is now conditional
  (`id + snapshot status + updated_at < cutoff`, `synchronize_session=False`);
  refunds are issued only for rows whose DELETE actually won; dismissed-row
  clearing is a conditional UPDATE so a concurrent restore (dismissed→done)
  keeps its file/result.
- **Tests**: `test_extract_jobs.py` — double sweep refunds once; simulated
  claim-vs-sweep and restore-vs-dismissed-file races (SQLAlchemy
  `before_cursor_execute` hook) lose the race cleanly.

### 0.4 SSE quota could be refunded twice
- **Symptom**: the failure path refunded and then yielded the error event;
  a client disconnect at that yield hit the `GeneratorExit` handler and refunded
  again. Because the decrement clamps at 0, the second refund silently consumed
  an *earlier* legitimate extraction. There were two refund sites (pre-LLM and
  post-exception), only one of which the first attempt covered.
- **Fix**: `event_stream()` now routes all refunds through a per-stream
  `_refund_once()` guard (explicit failure, `CancelledError`, `GeneratorExit`);
  the "Extraction %s — quota refunded" log no longer claims "by client" for
  server-side failures.
- **Tests**: `test_ai.py::test_disconnect_at_error_yield_refunds_exactly_once`
  drives the endpoint directly, drains to the error yield and `aclose()`s the
  generator (asserts one refund).

### 0.5 Merged readings leaked into flowsheet + print
- **Symptom**: documented contract says merged readings appear ONLY in the
  timeline details view, but `flowsheet.py` loaded all readings, set a
  `MatrixCell.merged` flag that no client ever read, and the frontend rendered
  them as normal cells — in the flowsheet matrix AND in the print/export
  payload (`biomarkers` list) and correlation.
- **Fix**: the flowsheet readings query filters `merged IS FALSE` (single
  source of truth); removed the now-dead `MatrixCell.merged` from the backend
  schema, serializer and frontend types; architecture doc updated.
- **Tests**: `test_entries.py::test_merge_excluded_from_flowsheet` (timeline
  still surfaces the merged reading; flowsheet matrix + biomarker list do not).

## Phase 1 — done (user-visible correctness & UX)

1. **`status: ""` (unknown) rendered as abnormal — fixed.** New single source of
   truth `isOutOfRange()` + `Status` widened to include `''`
   (`lib/status-labels.ts`, `lib/types.ts`); neutral "Unknown" badge
   (`StatusBadge`), flowsheet/print cells no longer bold-red/starred,
   `entry-settings` counts `''` separately (`statusBreakdownUnknown` key,
   never `NaN`), `results-panel` sort ranks it last. Display sites fall back
   to `statuses.unknown` instead of an empty chip. Tests: `status-labels`,
   `status-badge`, flowsheet-matrix, print-editor, entry-settings.
2. **`ReferenceInput` external sync — fixed.** Identity-compared against the
   last locally emitted object (typing keeps its trailing decimals), an
   externally supplied definition reference is adopted and survives the next
   edit instead of being wiped. Tests: `reference-input.test.tsx`.
3. **Auth-readiness races — fixed.** `useBiomarkerData` (query key now
   `['biomarker', uid, …]`, gated, `isLoading` covers session resolution),
   `usage-card`, `PrintEditorView` (+ abort guard) gate on
   `authReady`; register-page anon-data probe is skipped for authenticated
   visitors and for the loading window.
4. **Anonymous session cookie — fixed (persistent).** `Max-Age` = 30 days
   (`ANONYMOUS_COOKIE_MAX_AGE_S`); test asserts the `Set-Cookie` header;
   architecture doc updated. Decision log below.
5. **Mobile blockers — fixed.** add-entry preview/form stack below `lg`
   (preview capped at 60vh); `LabResultForm` grid scrolls horizontally
   instead of clipping; correlation stacks with usable card heights and
   `min-h-screen lg:h-screen`; print editor stacks the sidebar (capped 45vh)
   and uses `h-dvh`.
6. **Error/empty states — fixed.** Imports tracker: retryable error state and
   toasts on failed cancel/retry/dismiss; timeline/flowsheet/correlation use
   a shared `LoadErrorState` with a retry button and user-facing copy (no more
   "Is the backend running?"); forgot/reset-password go through new
   `requestPasswordReset`/`resetUserPassword` shared-API helpers (proxy-only,
   Accept-Language, 422 `detail` arrays rendered as text instead of crashing);
   failed registration auto-login now toasts "Account created — please sign in"
   before redirecting.
7. **Type-switch data loss — fixed.** `TypeSwitchConfirmDialog` asks before a
   document-type change resets the form when real data is present.
8. **Deferred to Phase 2**: duplicate pairwise correlation computation;
   `gapAwareLineShape` className continuity; print-editor one-shot filter
   initialization (currently masked by the single fetch).

## Phase 2 — hardening, hygiene, stale artifacts (planned)

### Robustness / security
- Unlink-before-commit on entry delete (`entries.py` delete path) and no
  orphan-file safety net on merge (`entries.py` merge path) — failures can
  leave DB rows pointing at deleted bytes or stray files on disk.
- `auth.py`: throttle map grows unbounded for one-shot keys; reset-token
  single-use is not atomic; no password length cap (bcrypt truncates at 72
  bytes); stale reset-token purge rolls back for unknown emails.
- `data_migration.py` copies definitions with the legacy `local-{uuid}` id
  format that startup migration immediately rewrites.
- OCR retries non-retryable failures up to 6× (worst case ~minutes per bad
  upload); `chat_client` doesn't retry network errors despite documented
  bounded retries; `timing_stats` bypasses the sessionmaker seam.
- `scripts/cleanup_e2e_data.py` uses a raw DELETE (no cascades, doesn't free
  files/quota) against the real dev DB.
- Storage-quota decrement doesn't clamp at zero; `_localized_error` renders no
  text for catalog keys that were removed; `ExtractionJob.saved_entry_id`,
  `ImportFunnelEvent` and `CategoryTranslationCache.created_at` are
  write-only.

### Frontend hygiene
- `DocumentViewer` never destroys the pdf.js document/worker; print-iframe
  leak in `lib/utils.ts`; `ModalDialog` unstable `onClose` dep steals focus;
  `unit-conflict-dialog` stale `choices` state; nested-button bubbling in
  `notification-bell`; `add-entry` `Date.now()` key collisions.
- Dead exports/deps: `zustand` (unused), `shadcn` in runtime deps,
  `ReactQueryDevtools` always bundled, ~15 unused exports.

### Docs / copy
- `addEntry.multiFileNotice` still says "Only the first document is processed"
  (pre-batch-import copy).
- Imports tracker wording drift ("Imports" vs "Back to timeline" both navigate
  to `/imports`); unused `reviewMergedToast`; `trackerActiveTitle` never
  rendered; print-setup duplicated comment block.

## Verified-OK (invariants that held during the audit)
- `/api/extract` worker commit-before-close; status persisted at save; `kind`
  sole discriminator; lg→linear anchoring and deterministic scale functions;
  specimen-aware matching guards.
- Batch import lifecycle: quota charged at submit, refunded only on winning
  CAS; staged results; `saved` history rows; one notification per terminal
  transition; SSE `/api/extract` path untouched by import code.
- Event-type vs status color channels; inferred-unit flag only in the
  add-entry editor; merged-readings timeline gating (`isLatest`) — all
  preserved.

## Decision log
- Anonymous session cookie persistence: **bug → fixed in Phase 1.4**
  (`Max-Age` 30 days).
- Merged readings excluded server-side from `/api/flowsheet` (Phase 0.5);
  `MatrixCell.merged` removed as dead API surface.
- `procedure` remains a savable entry type; only `unknown`/garbage is rejected.
- Unknown reading status (`""`) renders as a neutral "Unknown", never as
  abnormal; it sorts last but is never counted as a flag.
